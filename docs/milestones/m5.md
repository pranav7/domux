# M5: launchable

M5 is the release: four builds behind a tag, a curl installer in front of them, and the license
and attribution that let someone else run the binary. Decision record 0039 holds the choices;
this file says what shipped and what is still open.

## What shipped

**The version.** `[workspace.package].version` is `0.1.0`, and `domux --version` prints
`domux 0.1.0` on a tagged build and `domux 0.1.0 (<git describe>)` on any other, so a binary
always says which commit it came from. `crates/domux/build.rs` records the describe, and the
pipeline overrides it with the tag because a shallow checkout has no tags to describe. The
release first shipped as 1.0.0 and was rebuilt as 0.1.0; decision record 0048 says why.

**The release profile.** `lto = "fat"` and `codegen-units = 1` for size and speed,
`strip = "debuginfo"` to drop DWARF while keeping symbol names, so a stranger's backtrace still
names functions. `panic = "unwind"` stays: the client restores the terminal while unwinding, and
a panicking task must not take down the server that owns the panes. `cargo build --profile
profiling` is the same code with symbols.

**The license.** Apache-2.0 in `LICENSE`, `NOTICE` for the Ghostty library compiled in, and
`THIRD_PARTY_LICENSES.md` generated by cargo-about at release time. `sh tests/license/run.sh`
checks the files and CI checks every compiled crate's license against `about.toml`.

**The release scripts**, under `scripts/release/`, each one a shell script with its own tests in
`tests/release/run.sh`:

| Script | What it does |
|---|---|
| `check-version.sh` | the tag is a version and equals `[workspace.package].version` |
| `changelog-section.sh` | prints one version's `CHANGELOG.md` section, fails when it is missing |
| `build-archive.sh` | builds one target, signs it on macOS, packs the archive and its checksum |
| `smoke.sh` | extracts an archive, runs `--version` and `api schema`, checks no server started |

**The pipeline.** `.github/workflows/release.yml`: `check`, then `build` over four targets, then
`smoke` on a runner of each archive's own platform, then `publish`, which assembles
`SHA256SUMS`, verifies it, and creates the GitHub release with the changelog section as its
notes. A `workflow_dispatch` run does everything except publish.

**The installer.** `install.sh` at the repository root, served from the raw URL on `main`. It
prints the domux logo, detects the platform, picks the newest release or `DOMUX_VERSION`,
verifies the checksum before extracting, installs into `~/.local/bin`, and installs the hooks for
every agent already configured, one line per agent. Then it asks for the leader and whether to
set up stay awake for a closed lid, and writes the answers to the config file without replacing
anything already set there (decision 0043). A finished step wears a check mark, and the release
lookup and the download turn a spinner while they wait. One line on stdout: the installed path
and the version. `tests/install/run.sh` covers every branch with a fake curl, uname, ldd and
sudo, runs the spinner and the questions on a terminal where util-linux `script` is there, and CI
runs it under dash, bash and macOS's sh.

## What is still open

- **V1's README does not point here.** The Go version's code is the `v1` branch and its
  releases are retired (decision record 0048), but no notice at the top of its README says where
  the Rust version is.
- **The stranger test has not been run.** M5's exit criterion is that a stranger installs on a
  Mac and on Ubuntu in under five minutes and sees an agent's state. Nobody has been timed yet.
- **Only the arm64 macOS archive has been built outside CI.** The other three are the pipeline's
  first run.
